Kalam design study v2, production preparation

Three indicators, every state, and the picker

The exploration phase closed with A machined instrument, E whisper pill and H caret chip standing. This round flushes all three across the complete five-state matrix, defines the fallback law that lets tiny indicators survive situations they cannot represent, and designs the Settings picker inside the real Compass Being-heard pane, extending the D-1E menu grammar rather than inventing new chrome. Everything here is written against implementation: state names, config key, migration note, and the K-36 dependency are called out where they bind.

Listening tiles simulate a live mic. Reduced Motion honored automatically.

H. At the caret

chip states plus the fallback path

The chip lives only while there is a caret to anchor to, and it trails the caret: text, then the thin caret bar, then the chip, so the indicator occupies empty space ahead of the insertion point instead of covering the words just dictated. Transcribing, held, blocked and any failed caret resolution all route to the A form; the chip fades as the text lands.

Settings: choosing between the three

inside the real Compass pane

Built on the Compass Being-heard screen, extending its own D-1E ruling: the indicator control is a single-select menu anchored to its row, text rows plus checkmark, no toggles. Style becomes its own row beside the existing Position row, and a preview strip under the Behavior card carries the visuals, using the v3.2 device-row pattern of accent-selected tiles with a mono sublabel. Tiles are clickable too; direct manipulation beats menu archaeology for a three-way visual choice.

Implementation notes

what ships in which order
Phase 1, no dependencies: A restyle (tokens, layers), E pill window, state machine rename to the five canonical cases, Settings row + preview strip. Everything except H and clickable held buttons.
Phase 2, needs nothing new either: H chip. Caret rect arrives from AccessibilityFocusResolver, which already runs at record start. Fallback routing is a guard clause.
Phase 3, gated on K-36: making held and blocked buttons actually clickable. The UI exists from day one; only the click-through fix turns them live.
Out of scope by earlier rulings: light mode for A beyond the opt-in follow-appearance setting (token set already demonstrated in v1.4), any rejected-ledger direction.

Reference package only. Live indicator: app/Kalam/DictationOverlayController.swift. Settings grammar authority: kalam-compass-swiftui-v1.3.8/spec screen D-1E. Accepted changes land in the live files and nowhere else. Copy follows house rules: no em dashes, no mid-dot compounds, no absolutes.

B variant (shipped 2026-08-26)

no dwell

B shipped as implemented in DictationOverlayController.swift: whisper listening shows a slow 3.6s clockwise green ring (ambient, one turn per take) and every transcribing state shows the same ring at a faster 2.4s with its blurred glow twin; caret listening never shows a ring (chip trails the caret with green dot and bars only) and machined listening never shows a ring (waveform is the hero). Spec authority for the speeds and gating is contrast-remedy.html § speed & dwell study. No other sections of this v2 spec were restructured for this addendum; existing state matrix, fallback law, and Settings picker remain as written.
