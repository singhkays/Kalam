Doc strategy

Why not one mega-HTML?

One 3k-line file mixes two audiences and two change rates. Mockups churn when design tweaks a well; the contract churns when the store API is named. Agents paste the wrong half into context. Split by job, not by version.

FileOwnsDoes not own
compass-mockups.htmlEvery 980×660 frame, on-screen copy, visual statesProtocols, persistence, Swift file tree
compass-impl.htmlTypes, store, tokens, traps, migration, planRedundant full mockup gallery
Settings/Compass/*.swiftRunnable stubs matching the contractProduct copy invented off-spec
index.htmlEntry + how to read the setNormative rules
Rejected alternatives. (1) One giant HTML — context bloat, merge pain. (2) One HTML per screen — navigation hell, token drift. (3) Markdown-only — mockups need pixel fidelity. (4) Figma link as SoT — agents cannot grep it. Two HTML + Swift tree is the stable split.
Spelling. Entire Compass UI and this contract use American English: behavior, behaviors, Normalize, license (noun). Do not re-Britishize from the live app or old V1 strings.

Types

Shapes that ship

struct KeyChord: Hashable, Codable {
    var keyCode: UInt16
    var modifiersRaw: UInt  // NSEvent.ModifierFlags.rawValue
    var side: KeySide
    var displayVerbose: String  // map title: "Right Command"
    var displayCompact: String  // keycap / contents: "Right ⌘"
}
enum KeySide: String, Codable { case left, right, either }

// Capture: click keycap → local keyDown monitor. Escape or second click cancels.
// Bare modifiers allowed. Reject unstable keys with dashed flash + "That key cannot be used." (800ms).
// No Clear button. No preset catalogue. System shortcut conflicts: accept silently.

enum ActivationMode: String, CaseIterable, Codable {
    case holdOrToggle, toggle, hold, doubleTap
    var mapDescription: String {
        switch self {
        case .holdOrToggle: "Hold or toggle."
        case .toggle: "Toggle."
        case .hold: "Hold."
        case .doubleTap: "Double tap."
        }
    }
}

enum EnginePresence: Equatable {
    case verified(ModelInfo)
    case missing
    case incomplete
}

enum DictionaryEditorPhase: Equatable {
    case browsing, adding, editing(UUID), confirmingDelete(UUID)
}

Accessibility

Text carries state

  • Close “Close”; Back “Back to overview”.
  • Map card “{dest}, {state}, {title}”; Open → decorative hidden.
  • State dots ignored by VoiceOver.
  • Privacy not a live region.
  • Fixed Dynamic Type.
  • Reduce motion: no map hover lift; toggle snaps.
Build plan

Order

  1. Read mockups index once (all frames).
  2. Wire CompassSettingsBacking to live store; keep InMemory for previews.
  3. Window shell 980×660 plain drag dismiss Cmd-W privacy once.
  4. SettingsModel derived attention/spanning/hero + fixtures.
  5. MapView all map states including M.8.
  6. Nav path 0/1 + Dive chrome + ContentsNav.
  7. Panes: BeingHeard (empty/permission/menu), Trigger (capture/reject), Cleanup (wells), Dictionary (phase machine), Engine (missing/incomplete), Updates.
  8. Live refresh + first-rule map flip.
  9. A11y labels.
  10. Stop — no dark mode, network, file checklist, preset hotkey menu, bulk import.
Acceptance

Done when

  • M.1 → Dictionary → add rule → Back shows M.2; privacy line stable within session.
  • Incomplete → M.8 + D.5c strings (not missing).
  • D.1c / D.1d correct empty vs permission.
  • D.1e menu anchored to chip; no toggles; no overlay on Behavior switches.
  • Cleanup master off dims rules; values preserved.
  • Updates never URLSession.
  • No Compass-* UserDefaults keys.
  • UI strings American English.
  • Dictionary delete works; mic IN USE is first connected.
If lost. Mockups for pixels. This file for law. Swift stubs for names. Do not invent a third root screen.
